VRDesktopHUB 扩展开发手册

面向独立 MOD 作者。扩展 API 1.10，适用于 Alpha144，Windows x64、.NET 10。本手册是开发入口；SDK 的 lib/Contracts.cs、lib/ExtensionBase.cs、lib/BackendEvents.cs、lib/HostContext.cs 是准确的公开 C# 签名。无需引用或阅读 VRDesktopHUB 的 Runtime、Overlay、Extensions 实现。旧 API 1.0–1.9 包仍按自己的清单协商；基类和原辅助调用最低1.4及 sdk.base，后端事件另需最低1.5及显式协议声明。语义排版另需最低1.6及 ui.presentation；实例设置页另需最低1.7及 management.instance-pages；小部件操作栏另需最低1.8及 widgets.toolbar；窗口上下文另需最低1.9及 view.window-context。宿主快照、订阅和自身窗口请求分别需最低1.10及 host.context、host.subscriptions、view.requests。

公开阅读入口：发行仓库中的开发手册。Alpha144 发行页面另附可下载的离线 HTML 和 Markdown。手册附件仅含文档；下文的开发工具包由维护者单独导出。

1. 从空目录开始

维护者在源码根目录导出开发工具包：

powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-extension-sdk.ps1

工具包位于 artifacts/latest/extension-sdk，可以整体复制给作者；不需要私有源码。包含公开SDK DLL/声明、校验打包工具、独立测试工作器、项目生成脚本和本手册。SDK依赖.NET 10，不包含VRDesktopHUB应用主程序或用户数据。

工具包同时包含本手册的离线 HTML，支持目录、搜索和复制代码。维护者导出 SDK 另需 PowerShell 7，用它从 Markdown 自动生成 HTML；作者使用工具包不需要重新生成文档。

作者在任意自己的开发目录中执行（将下面 SDK 路径换为实际位置）：

$sdk = 'C:\VRDesktopHUB-ExtensionSDK'
powershell -NoProfile -ExecutionPolicy Bypass -File "$sdk/new-extension.ps1" `
  -Id org.example.hello -Name '我的文字板' -OutputDirectory .\hello
powershell -NoProfile -ExecutionPolicy Bypass -File .\hello\build.ps1
dotnet "$sdk/tools/VRDesktopHUB.ExtensionTools.dll" validate .\hello\package --json
dotnet "$sdk/tools/VRDesktopHUB.ExtensionTools.dll" pack .\hello\package .\hello-1.0.0.vrdhmod.zip

若 SDK 搬过位置，构建时传 -SdkDirectory <新路径>，或 dotnet build ... -p:VRDesktopHUBSdk=<新路径>。生成器不覆盖已有项目；打包器不覆盖已有包。退出码0成功，非0失败；--json 输出单个 JSON 结果。校验、打包只检查文件和声明，不加载 MOD DLL，也不执行其代码。

生成的 src/ 是源码，package/ 才是可安装 MOD：

hello/
  src/Mod.csproj, Mod.cs
  build.ps1
  package/
    manifest.json
    bin/Mod.dll
    languages/zh-CN.json, en-US.json
    schemas/save.json
    views/initial.json

把 package 整个文件夹 复制为程序的 mods/hello/，或将 ZIP 放入程序 mods/，两种选一种。运行中的程序会发现它；扩展页启用并明确授权本机代码，进入“管理”编辑文字，再从“小部件 → 创建小部件”创建显示。也可在扩展页导入 ZIP/目录；导入副本，原位置后续修改需要重新导入。

开发时编辑程序 mods 内来源的 JSON/资源可自动重载；代码仍由作者编译后复制 DLL/依赖。不需要改版本号或反复导入。不要编辑用户目录的 mods/installed 缓存。坏构建保留上一版；来源移走会停止它，放回后恢复原内容。首次发现不会自动启用。

不启动主程序的真实运行验收

工具包还包含独立工作器。run 会执行你指定的 MOD 代码和后端，只使用新的隔离注册表与数据目录，不安装到日常应用，也不启动 SteamVR。源码开发与 CI 都可以用它；它验证真实进程和接口，不验证 Windows/VR 像素排版。

为生成器的文字板保存以下 scenario.json：

{
  "capabilities": [],
  "steps": [
    {"op":"create","name":"card","type":"content","title":"验收文字板"},
    {"op":"open","name":"panel","kind":"widget","contribution":"panel","instance":"card"},
    {"op":"open","name":"editor","kind":"management","contribution":"settings"},
    {"op":"invoke","view":"editor","action":"save","parameters":{"message":"独立开发成功"}},
    {"op":"state","path":"/message","equals":"独立开发成功"},
    {"op":"invoke","view":"editor","action":"save","parameters":{"message":" "},"success":false},
    {"op":"state","path":"/message","equals":"独立开发成功"},
    {"op":"close","view":"editor"},
    {"op":"close","view":"panel"},
    {"op":"dormant"}
  ]
}

dotnet "$sdk/tools/VRDesktopHUB.ExtensionTools.dll" run .\hello\package .\scenario.json .\new-run --json

每次使用新输出目录。steps.json记录逐步结果，snapshot.json保存退出前的上下文、视图与动作，store/保存隔离数据供排错。name为create/open的引用名；instance和view引用这些名字，不把临时GUID写死。invoke默认期望成功，success:false期望拒绝，可用errorContains核对原因；state用JSON Pointer定位自己的包级或实例数据，指定instance时读该实例。

API1.7 实例设置使用 {"op":"open","name":"camera-editor","kind":"management","contribution":"camera-settings","instance":"camera"}，其中 camera 引用前面的 create；不带 instance 仍打开旧全局页。场景顶层可放 "initialGlobal":{...}，仅在本次隔离 store 导入后、启用前初始化包级数据；例如预设本地测试端点，避免先运行真实自动发现再修改配置。它不是生产配置命令，不访问用户安装数据。

其他步骤：{"op":"enabled","enabled":false}、{"op":"feature","feature":"main","enabled":false}、{"op":"capability","capability":"workspace.read","granted":true}、{"op":"delete","instance":"card"}、{"op":"crash"}（仅结束本测试工作器）。重新启用后重新open管理页，旧页不能复用。open可指定language。纯操作栏动作的invoke不填view，实例动作加instance。run没有真实VR宿主，workspace/capture/runtime的应用能力可能返回host_unavailable/vr_unavailable；这不等于真实应用未实现该能力。

需要把运行时生成的实例 ID 放进动作参数时，使用精确对象引用："parameters":{"value":{"$instance":"card"}}。工具将这个对象替换为card的真实GUID字符串，普通文本和其他对象不改。引用只在本次场景内解析，不是MOD协议的一部分。

可用以下步骤检查中间结果，避免只看末尾快照：

{"op":"view","view":"panel","path":"","contains":"独立开发成功"}
{"op":"action","action":"save","enabled":true,"busy":false}
{"op":"checkpoint"}

view定位到已打开视图的ViewDocument，path为JSON Pointer；equals精确比较JSON，contains递归检查字符串内容（支持中文）。action核对指定动作的enabled/checked/busy；实例动作需加instance。checkpoint把当时页面、上下文、动作和运行状态保存到snapshot-序号.json，不是像素截图。

state/view/action默认立即断言。请求返回queued后，完成事件可能在后续回调才到达；用{"op":"state","path":"/status","equals":"failed","wait":true}等待条件，最多7秒。view和action同样支持wait:true。等待只在显式测试步骤中运行，正常宿主不增加轮询；不要用立即读到queued推断没有完成事件，也不要在MOD动作回调内阻塞等待它。

{"op":"external-state","data":{"message":"其他编辑者保存的内容"}}在本次新建的隔离store使用真实原子保存更新全局数据；加instance可指定本次创建的实例。工作器不收到额外通知，下一次使用旧Revision保存必须冲突。用它验证拒绝覆盖、显式重读及合并；它不是生产宿主命令，不能写日常应用配置，也不模拟业务保存成功。测试数据必须符合你自己的数据结构。崩溃不会自动重新执行有副作用的动作；通过enabled:false、enabled:true显式恢复，再重新open视图。

2. 选择实现形式

需求 实现
静态文字、按钮打开内容、键盘/主题等提供者 runtime.kind: none，只交付 JSON 与资源
原生表单、业务逻辑、保存、宿主调用 托管 ExtensionBase 或 IExtension，结构化 UI
与宿主完全不同的视觉 托管前端生成 PNG，发布 surface；目前只回传确认点击
独立程序或其他语言后端 托管前端 + 包内 EXE，使用标准输入输出 JSON 分帧；后端不限语言

本机代码可以调用普通用户有权访问的系统库、文件、网络及自己的依赖；代码授权不是沙箱。宿主的 VR、输入、工作区、捕获对象不作为可变引用交给 MOD，需要通过能力命令操作。宿主以普通用户令牌运行前后端，管理员主程序也不会把管理员权限传给 MOD。

结构化控件由宿主提供 Windows/VR 渲染、滚动、文字输入和草稿；MOD 不需要业务分页。空间窗口、移动、缩放、吸附和收起统一由宿主管理。业务管理页的内容和行为由 MOD 定义。

3. 包清单与注册关系

一个 MOD 的多个功能小部件

一个 MOD 可以在 contributes.widgets 声明多种小部件；每种使用独立的 id、标题、初始视图和 instanceTypeId。独立功能分别映射到 instanceTypes 中的业务类型，使用 featureId 控制该功能。supportsMultipleInstances 在业务类型上控制是否可以创建多个内容实例。

包级设置和外部连接由 MOD 共享，具体部件配置存入对应实例数据。例如一个工具箱同时提供聊天、参数控制和状态小部件，仍只启动一份包级工作器和至多一份清单声明的独立后端。不能为每次打开视图重复建立连接；关闭视图也不能删除业务实例或停止其他部件。一个实例需要小部件和表盘两种展示时，可让这两种入口引用相同业务类型。

当前每包最多声明16种小部件、32种业务类型；宿主全部 MOD 合计最多64个业务实例。“种类”“内容实例”和“展示视图”不是同一个计数。所有可用小部件均通过宿主统一创建列表进入，停用的 MOD 或功能不出现。

公开契约与宿主边界

ExtensionContracts 是独立的插件契约库，不依赖 Runtime、Project、Core、WPF 或 OpenVR；第三方只引用公开 DLL。宿主通过能力桥接执行工作区、捕获等真实操作，MOD 不得引用主程序私有类型。这是独立契约加主程序宿主适配，能力协议仍具有 VRDesktopHUB 的业务语义；当前请求和结果采用字符串与 JSON 约定，运行工作器也仍限定 Windows，不能称为与宿主无关的完整抽象层。HTML 手册不代表支持 HTML 运行时 UI。

主程序更新与兼容

主程序 Alpha/build 版本、扩展 API、MOD 包 version 和业务 dataVersion 分开管理。当前宿主保留 API1.0–1.4，按包声明的 [min,maxExclusive) 与必需特性选择可用版本；窄范围保留对应旧版本，宽范围仍选择最高兼容版本。API1.x 的公开契约程序集身份固定为1.0.0.0，新增能力不要求旧包重新编译。旧接口不能删改或增加必需实现成员；不兼容的主版本明确拒绝，不能静默替换。

宽范围并不自动开启全部新行为。视图/动作发布等待宿主校验确认的行为，要求包明确声明最低API1.4；较早最低版本的包保留原通知语义，即使本次协商出的最高版本为1.4也不变。使用新SDK时应声明真实最低版本及特性。

可以查看 SDK 内 compatibility.json，或查询同一份兼容描述：

dotnet "$sdk/tools/VRDesktopHUB.ExtensionTools.dll" compatibility --json

主程序更新保留程序 mods/、已安装包、业务数据、实例与工作区配置。宿主升级不会自动提高 MOD 的 dataVersion；插件自身数据迁移只在候选代际执行，失败保留旧版。不兼容包仍可停用或卸载，默认保留数据，不影响其他 MOD。作者应保留交付的原始二进制，用新版宿主验收，而不是每次重编译掩盖兼容问题。

清单内容

以下为 API 1.4 托管包的最小结构。完整可运行版本由生成器产生，不能仅拷贝清单而缺少 DLL、语言、视图和 schema。

{
  "manifestVersion": 2,
  "id": "org.example.hello", "version": "1.0.0",
  "nameKey": "name", "author": "Your name",
  "defaultLanguage": "zh-CN",
  "languages": { "zh-CN": "languages/zh-CN.json", "en-US": "languages/en-US.json" },
  "api": { "min": "1.4", "maxExclusive": "2.0" }, "dataVersion": 1,
  "runtime": {
    "kind": "managed", "entryAssembly": "bin/Mod.dll", "entryType": "MyMod.Extension",
    "targetFramework": "net10.0", "runtimeIdentifier": "win-x64"
  },
  "capabilities": { "required": [], "optional": [] },
  "requiredFeatures": ["sdk.base", "ui.basic", "widgets", "instance-types", "content-views", "features"],
  "contributes": {
    "features": [{ "id": "main", "titleKey": "name" }],
    "instanceTypes": [{ "id": "content", "titleKey": "name", "supportsMultipleInstances": true, "featureId": "main" }],
    "widgets": [{ "id": "panel", "titleKey": "name", "initialView": "views/initial.json", "instanceTypeId": "content", "featureId": "main" }],
    "wristPages": [], "actions": []
  }
}

ID 使用反向域名风格、仅小写字母数字点和连字符，不使用保留的 vrdesktophub.。清单版本2是包格式，api 是接口协商范围，version 是 MOD 版本，dataVersion 是业务数据版本，四者不能混用。JSON 字段名使用上例 camelCase，未知字段报错。所有包内路径使用正斜杠相对路径，禁止绝对路径、..、链接和大小写重复路径。ZIP 根层直接包含 manifest.json。

每个 instanceType 定义一种有 ID、名称及独立数据的业务内容；widget/wrist/action 定义显示或操作它的入口。多个入口可以共享同一 instanceType/instanceId，不能为同一份业务数据各造一个对象。没有业务实例的管理页或纯动作不需要假小部件。

同一业务功能的类型、视图、动作与提供者共用一个 featureId，例如计数器的加一、归零、表盘与小部件属于同一个功能。宿主负责关闭这些入口；MOD 有自己的后台工作时实现可选 IExtensionFeatures.FeaturesChangedAsync 停止相应工作。

注册项 关键字段与附加特性
业务类型 instanceTypes: [{id,titleKey,supportsMultipleInstances,featureId?}]；instance-types，API≥1.1
小部件 widgets: [{id,titleKey,initialView,instanceTypeId,featureId?,size?}]；widgets、content-views
表盘 wristPages: [{id,titleKey,instanceTypeId,initialView,featureId?}]；wrist-pages
动作 actions: [{id,labelKey,parameterSchema,target,instanceTypeId?,kind?,toolbar?,handler?,icon?,featureId?}]；actions
管理页 managementPages: [{id,titleKey,initialView}]；management-pages，API≥1.1，代码实现 IExtensionManagement
实例设置页 管理页增加 instanceTypeId；同时声明 management-pages、management.instance-pages，API≥1.7；设置直接嵌入小部件编辑区
功能 features: [{id,titleKey}]；features，API≥1.2
提供者 providers: [{id,slot,titleKey,value,version:1,featureId?}]；host.providers，API≥1.2

动作 target 为 instance 或 extension，默认 instance；前者必须给 instanceTypeId，调用时带该 MOD 对应类型的实例 ID，后者目标 ID为null。kind 为 command/toggle。toolbar 为 none/toggles/functions，显示到操作栏时需包内 PNG icon及 actions 特性；用户明确绑定后显示。handler 默认 extension；host.openWidget 需 widgetTypeId，交给宿主打开该展示。用非空 schema 描述动作参数，不靠 C# 转型后才检查输入。

当前开发版每包最多声明128个动作，运行时完整动作状态快照最多2048项（实例动作按各实例分别计数）。设置保存应声明独立动作，不借用聊天发送、实时控制等动作并塞入不相关参数。超过声明上限时校验器定位到 manifest.json /contributes/actions；消息大小、速率、租约和运行状态限制仍独立适用。

size 使用 Width/Height 对应的 camelCase 字段 width、height、minWidth、minHeight、maxWidth、maxHeight；默认560×280，最小360×240，最大960×714。控制容器排版，不能改空间抓握语义。

4. 生命周期与调用约定

ExtensionBase 只简化 IExtension 空回调，不隐藏存储、线程或自动重试。覆盖 OnInitializeAsync，Context已可用；不要重写 InitializeAsync。可选接口仍显式声明。

回调 作者的工作
OnInitializeAsync 从 Context.Bootstrap.Global 恢复包级数据，记住 Revision；读取 GrantedCapabilities、协商 ApiVersion、Features
CreateInstanceAsync 返回新实例初始 JSON；此时宿主尚未提交实例，不能先保存它
RestoreInstanceAsync 从 InstanceContext.State 恢复实例数据和修订，Name是用户命名；不是每次打开视图都新建数据
UpdateViewContextAsync 保存 ViewContext并按尺寸、语言、字号、Visible发布内容；基类的 AttachViewAsync会转到这里
InvokeAsync 执行动作，参数已按 schema 验证；业务拒绝返回 new ActionResult(false, reason)
DetachViewAsync 移除这个 ViewId 的展示缓存，不删除业务内容
DeleteInstanceAsync 移除已删除实例的本地缓存；宿主已撤销其存储权限
MigrateAsync 数据版本变化时返回转换后的 JSON，不写活动数据；失败拒绝更新并保留上一代
ShutdownAsync 结束自身资源和任务；正常休眠也会退出工作器，不能把进程内存当存储

宿主串行调用业务回调。作者创建自己的线程/异步任务时，需要自己保护业务状态；不要阻塞回调等用户操作，不在回调里 .Wait()/.Result 等待宿主请求。await 调用宿主与后端，不把后台任务当成永久进程。回调/IPC有超时；需要长任务时立即发布 Busy状态，在自己的任务完成后发布结果，并响应取消/关闭。

最后视图离开且无操作入口使用时，约2秒后释放普通工作器及其后端；关闭的管理页15秒未续租会失效。声明并获准 lifecycle.background 的 MOD 在启用后即使没有视图也会启动、保留工作器；独立后端仍由 MOD 在初始化或业务需要时启动，宿主不会代替作者连接服务。以 Context.Bootstrap.GrantedCapabilities 判断实际授权，不以 manifest 声明代替授权。需要保留旧版按需生命周期时，可将它声明为可选能力：获准后在初始化中启动后台业务，未获准时维持按需工作，并在管理页说明差异。停用 MOD 或撤销该能力会结束对应后台生命周期。

5. UI、修订与动作

发布页面：

await Context.PublishViewAsync(new ViewSnapshot(
    view.ViewId, view.ActivationId, view.ContextRevision, ++revision,
    new ViewDocument(1, new UiNode("text", "message", Content: new UiText(Text: message)))), ct);
await Context.PublishActionsAsync(new ActionStateSnapshot(++actionRevision,
    [new ActionState("increase", instanceId, Enabled: true)]), ct);

ViewId、ActivationId、ContextRevision来自当前上下文；不能缓存旧上下文后继续发布。Revision对每个视图单调递增；动作状态的Revision独立单调递增。发布所有可用动作状态的完整快照；实例动作必须用对应instanceId。动作被省略、Enabled=false或Busy=true时不能调用。仅在数据或上下文变化时发布，静态内容无需循环刷新或写日志。

多行文字与长度

声明 API≥1.4 和 ui.text，使用 new UiNode("textInput", "body") { Multiline = true, MaxLength = 8000, TextValue = body }。MaxLength为1–16384，0表示默认16384，按UTF-16长度；必须足以容纳发布的初始值。表单与VR输入均执行长度限制，截断不会拆Unicode代理对。

任意业务结构的动作参数

旧包保持封闭的一层基本类型schema。需要嵌套对象、数组或可空字段时，声明API≥1.4及 actions.json。这是有边界的 JSON Schema 子集，不支持 $ref、正则、oneOf/anyOf或执行代码。根必须为object；字段可用object、array、string、number、integer、boolean、null，也可用type数组表示可空类型。对象明确写additionalProperties（false、true或额外属性的schema），properties/required可省略。支持enum、const、min/maxLength、minimum/maximum、min/maxItems、min/maxProperties，数组必须声明items。

{
  "type":"object","additionalProperties":false,"required":["items"],
  "properties":{
    "items":{"type":"array","maxItems":100,"items":{
      "type":"object","additionalProperties":false,"required":["title","done"],
      "properties":{"title":{"type":"string","minLength":1,"maxLength":128},"done":{"type":"boolean"}}
    }},
    "metadata":{"type":"object","additionalProperties":{"type":["string","null"]},"maxProperties":32}
  }

不要把业务JSON编码成字符串绕过结构校验。新参数正文≤64KiB、深度16、共4096个值，每对象≤256属性、每数组≤512项；schema≤256节点、嵌套8层。拒绝重复属性，错误含JSON Pointer路径。字段名≤128字符；integer按原始数值检查，不把小数四舍五入成整数。

管理页用 IExtensionManagement 的 UpdateManagementViewAsync / InvokeManagementAsync / DetachManagementViewAsync，发布仍用 ViewSnapshot，目标标识来自 ManagementViewContext。全局页不含伪造的业务实例或工作区；实例页由宿主提供真实 InstanceId，不能自行换成另一实例。

Windows 小部件列表复制会从已保存的实例状态创建新稳定 ID、独立存储，并调用正常恢复流程；插件应通过状态接口持续保存业务修改，不能依赖未保存的内存作为可复制内容。复制不创建工作区会话，不改变原实例；单实例类型、停用功能/包及超过64项不能复制，恢复失败撤销新实例和数据。

8. 独立后端与自绘

在runtime中增加：

"backend": { "executable": "backend/MyBackend.exe", "arguments": [], "protocol": "json-framed-v1", "timeoutMs": 2000 }

同时声明 runtime.backend。后端需要完整运行依赖；普通.NET console的runtimeconfig.json、deps.json、DLL和EXE一起放进backend/。

timeoutMs 允许100–4000毫秒（含两端），默认2000。executable必须是包内.exe；已有协议为json-framed-v1，事件协议json-framed-v2须按下节显式启用。arguments最多16项，每项最长1024字符且不能包含空字符。连接发现等长任务应快速返回操作标识，后续读取状态，不把游戏启动或长时间等待放进一次请求。该超时不是整段后台会话的存活期限。

前端调用：

var answer = await Context.RequestBackendAsync("calculate", new { text = "hello" }, ct);

stdin/stdout每条消息为4字节小端长度+UTF-8 JSON（1–65536字节）。请求 {id:GUID,method:string,parameters:object}；回复 {id:同一GUID,success:true,data:object}；业务失败为success:false、data:、error:string。stdout只写协议，诊断用stderr。每次一个在途请求；并发收到backend_busy，调用者排队。

首次请求才启动后端。业务拒绝保持健康进程；错ID、坏JSON、截断、超限、退出和超时回收该后端及子进程，后续明确重试才创建新进程，不自动重放业务请求。协议错误IOException、超时TimeoutException、业务拒绝InvalidOperationException。关闭、休眠、停用、前端崩溃均回收进程树。

8.1 后端事件订阅（API 1.5）

保持现有 RequestBackendAsync 方法、BackendEntry 构造签名和json-framed-v1协议不变。事件是可选增量：清单最低API1.5，requiredFeatures同时包含 runtime.backend、runtime.backend.events，runtime.backend.protocol显式设为 json-framed-v2。旧包不会因协商到较高API自动切换协议；老宿主会在执行代码前拒绝它不支持的新特性。

// 先订阅，再启动消费任务，随后仍通过原请求接口执行业务命令。
await using var subscription = await Context.SubscribeBackendEventsAsync(["sensor.changed", "job.completed"], lifetimeToken);
async Task Consume(CancellationToken ct)
{
    await foreach (var value in subscription.ReadAllAsync(ct))
    {
        // value.SessionId标识本次后端；Sequence允许有合并造成的空缺，仍严格递增。
        // 在自己的串行业务入口合并数据，只在内容变化时发布视图；此处不周期保存。
        ApplyEvent(value);
    }
}
var consuming = Consume(lifetimeToken);
var result = await Context.RequestBackendAsync("start", new { }, ct);
// 隐藏/关闭最后一个相关视图时Dispose订阅并结束消费；恢复时重新订阅并请求当前快照。

底层可选接口为 IExtensionBackendEventsContext.SubscribeBackendEventsAsync(string[], ct)，返回 IBackendEventSubscription（SessionId、ReadAllAsync、DisposeAsync）。一个订阅整个生命期只允许一次枚举；break、提前Dispose枚举器或取消会自动移除订阅，不能在同一个订阅上再次ReadAllAsync。包内多个小部件通常共用一份订阅再按实例分发，不必每窗新建订阅。确实需要独立消费时再各自订阅。订阅创建会启动后端并等到watch确认；业务请求仍最多一个在途，并发返回backend_busy，作者自行串行调度，不自动重试副作用。

订阅的CancellationToken或ReadAllAsync的取消只结束该订阅，不停止其他订阅/后端；Dispose会移除本地过滤并通知后端更新订阅集合。后端退出、超时、协议损坏或工作器休眠会结束所属会话的全部订阅；下一次显式请求/订阅可以启动新会话，旧订阅不会偷偷迁移或重放事件。消费循环应处理IOException/取消，并展示中断原因，让用户显式重连。不要在持有自己的业务锁时等待一个同样需要该锁的消费任务退出。

退订会立即停止本地交付，其异步清理仍需等待watch确认；如果业务请求正在处理，确认会排在该请求之后。事件到达时间应在foreach循环体内记录，不能把取一条后break并等待枚举器清理完成的时间当成到达时间。需要其他任务在收到首条时继续执行，可在循环体内完成TaskCompletionSource，再独立完成清理。

事件 BackendEvent(SessionId, Sequence, Topic, Data, Key) 有两种交付方式：Key=null是必须保留的FIFO事件，适合任务完成；Key非空则允许将尚未消费的同Topic/Key状态替换为最新值。替换项移到队尾，交付序号仍递增。可靠事件不会静默丢失；慢消费者超出限额时该订阅以backend_event_overflow明确失败，其他健康订阅继续接收。取消或Dispose会丢弃该订阅剩余队列，这是显式关闭。

每包最多8个订阅；每订阅1–32个互不重复的精确Topic，不支持通配符。Topic长1–64个ASCII字母/数字或 ._-；Key为1–128个UTF-16单元、不能全空白或包含空字符。每事件Data是已定义JSON（可为null），UTF-8不超过16KiB；每订阅队列最多64项及256KiB保守计费。v2读取流每秒4MiB预算，单帧仍≤65536字节。后端自己应合并高频状态，不能把每个输入包都变成一份UI或持久化写入。

后端可以只引用公开SDK，复用无宿主依赖的分帧服务：

var server = new BackendEventServer();
using var input = Console.OpenStandardInput();
using var output = Console.OpenStandardOutput();
await server.RunAsync(input, output, HandleRequestAsync, stoppingToken);

// await server.PublishAsync("sensor.changed", ExtensionJson.Value(new { value = 12 }), "sensor-1", ct);

文字 Content/Label的文字为UTF-8最多16384字节，Text与Key二选一；TextValue最多16384个UTF-16单元，输入另受MaxLength限制
数据 每份JSON≤512KiB，每包数据≤16MiB；无持续日志和心跳写入
通信 单条IPC≤1MiB，输入输出队列各4MiB，有界速率及超时

不要把完整业务地址、URL或长参数名直接当作选择项ID；使用稳定短ID映射到完整业务值，保留原始值，不截断业务地址。选择项Label用于显示，不受ID的64单元限制；select.TextValue必须对应某个UiChoice.Id，不能直接填其标签或完整业务值。

9.1 性能与进程隔离的边界

代码MOD及独立后端在主程序之外运行；插件业务阻塞或异常不直接占住VR线程的调用栈。但它们与主程序共享CPU、内存、GPU和磁盘，不能将独立进程理解为资源互不影响。普通权限也不等于CPU或内存配额。

结构化UI由宿主解析、布局、栅格化并上传纹理；自绘PNG仍需宿主解码和上传。复杂文档、高频变化及多个可见部件会增加主程序开销。消息大小、通信流量、节点数量、事件队列与超时用于限制输入和积压，不代表每帧CPU/GPU耗时保证；当前没有逐MOD硬性CPU/GPU配额。

作者应按实际变化发布视图和状态：后台按业务频率合并高频采样，状态事件用Key表示可替换的最新值，任务完成等可靠事件不要合并。多个视图优先共享一份包级订阅，再按实例分发；最后一个消费者离开即取消。经 lifecycle.background 授权的后台业务本身也可作为消费者，不应依赖视图可见性维持连接；停止该业务时取消订阅。不可见视图停止无用更新；配置只在真实变化时保存。发布与发送都要await，以实际背压调速，不能通过无限并发任务绕过预算。

性能验收至少比较扩展关闭、正常可见、持续高频更新和再次静止；分别记录主程序帧工作、纹理更新、插件CPU/内存和静置写入。局部渲染耗时、协议压力或SteamVR Null数据不能作为实体头显帧率保证。

常见错误：

  • 资源不存在：应交付package/，检查manifest中的bin路径；普通dotnet build的bin/Release不是包根。
  • 未知字段/不支持特性/API：JSON拼写或SDK/宿主版本不匹配，先validate；新类最低API1.4。
  • 动作没有反应：检查已声明动作、参数schema、完整ActionState、FeatureId、实例所属类型、当前View/ContextRevision及Enabled/Busy。
  • stale_context/management_view_closed：旧页面/旧激活/已关闭上下文，重新附加，不能对旧ID强行重发。
  • permission_denied：能力未声明或未授权，不是让插件取得管理员权限。
  • revision_conflict：保存用了旧Revision，成功保存后维护新Revision，不自动覆盖。
  • backend_protocol_error/backend_timeout：检查stdout帧格式、请求ID、依赖及超时。协议失败不等于应该自动重放。

发布前至少验证：新安装/无授权、正常授权、无视图休眠、重复打开、多个内容共用/隔离、失效回调、取消/坏输入、代码/资源热重载、保存去重、后端超时/崩溃/重试、更新迁移失败保留旧数据、卸载默认保留与明确清除。不要把能编译当作能运行，也不要把离线测试当作实体VR体验。

若受限自动化环境在任何业务步骤前报NamedPipeClientStream连接Access denied，先在普通用户终端用相同包和全新的run目录复现。它可能是父子进程令牌/沙箱隔离问题；不应给MOD申请管理员权限，也不应修改系统管道ACL来绕过。正常应用的管理员桥接仍由宿主负责。
